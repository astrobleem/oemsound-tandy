# Building the Winamp UI preview

Run `python HOST/RUN_HOST.PY` with a C89 compiler for the portable model tests. On Windows the runner adds the known UCRT compiler directory to its child-process PATH so cc1 can resolve its runtime DLLs. No global PATH changes or DLL downloads are needed.

The native build uses Microsoft C6, MASM5.10, LINK5.01.17 (`LINK4`), and the existing Windows3.0 SDK/DDK headers/import libraries. These proprietary tools are not supplied. In a fresh DOS build directory, copy SOURCE files and BROWSER source/headers/DEF/RSP into the same directory, then run BUILD.BAT. Adjust the C:\BIN, C:\INCLUDE, C:\DDK\286\INC and C:\LIB paths to your licensed tools. The application uses `/G0 /Gw /Gs /AS /W3 /Od`; the dialog DLL additionally uses `/Aw /Zp` and the no-CRT DLL library. DOSUTIL.OBJ must remain first in LWFILE.RSP because it supplies the reserved Win16 data header and LibEntry. MINIPLAY.RSP intentionally splits the object list with `+` for the old linker's response-line limit.

After linking, run `python HOST/NE300.PY MINIPLAY.EXE LWFILE.DLL PLBR.EXE PLLS.EXE PLPB.EXE` on the host. This records Windows3.0 as the expected version in the NE header; it does not change instruction generation or imports. Keep LWFILE.DLL beside MINIPLAY.EXE. The qualified clock/MCI/bridge files remain dependencies; their exact pins are in the test-pack receipt. No Windows3.1 COMMDLG is required.

PLBR, PLLS and PLPB are separate native UI harnesses using PLGUI.C. They write C:\PLGUI.LOG and exit Windows after completion. Each requests a 64-message queue and advances one bounded phase per 200ms NULL-window timer callback, returning to the main GetMessage loop between actions. Their DEF files export WndProc and ClockProc; timer creation, thunk creation and cleanup are checked. Dialog actions wait for visible owned windows, and completion waits for both dialog destruction and the player's return marker. The playback case samples progress while the modal browser is still visible. Use a fresh disposable 640KB Win3.0 real-mode image for each case, with the qualified Windows/audio profile; alias the chosen harness as RAWGUI.EXE when using the existing TPLAY /TEST path. Normal listening uses MINIPLAY, not the harness. Browser cases require original COPPER.VGM and F02..F05.VGM fixtures in C:\MMLAB; the latter are copies of the public synthetic SHORT.VGM. The host commands below reproduce these fixtures. No song imports or samples are needed.

Generate the original native UI fixtures on the host with `python HOST/MAKE_STUDY.PY INPUTS` and `python HOST/MAKE_UIFIX.PY INPUTS`. The latter reproduces the synthetic SHORT.VGM and its F02..F05 aliases byte-for-byte.

Use the shared emulator lease and a bounded owned-process watchdog where the workstation has concurrent emulator users. Native qualification does not install drivers or alter a CF card. The local private pack supplies the tested binaries, original fixtures and logs without Windows/ROM/toolchain files.

The public TWUX3.ZIP app bundle also includes DEPS with the matching audio/bridge source, the accepted EX/HX launcher policy and BUILD.BAT. Build those dependencies with the separately licensed period tools, then apply HOST/NE300.PY to the Windows DLLs. The app/browser build remains the SOURCE/BROWSER layout described above. Runtime pins are RUNTIME.JSON; no fresh rebuild or byte-reproducibility claim is made for this packaging-only publication.
